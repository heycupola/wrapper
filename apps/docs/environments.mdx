Wrapper runs in three settings: your **local** machine, a shared **dev**
environment, and **prod**. The repository root file `ENVIRONMENTS.md` is the
full reference with real deployment names and secrets; this page is the
overview.

## Components and hosting

| Component | What it is                                             | Hosting                      | Code               |
| --------- | ------------------------------------------------------ | ---------------------------- | ------------------ |
| backend   | Convex functions, auth (Better Auth), billing (Autumn) | Convex                       | `packages/backend` |
| relay     | Bun and Hono WebSocket relay                           | Fly.io                       | `apps/relay`       |
| web       | Next.js site                                           | Vercel                       | `apps/web`         |
| cli       | The `wrapper` CLI                                      | GitHub Releases and Homebrew | `apps/cli`         |

## Environment model

Two long-lived environments, selected by branch:

```text
local        your machine       Convex dev + ws://localhost:8080 + localhost:3000
dev branch   ->  DEV env    ->  Convex dev deployment, wrapper-relay-dev, Vercel Preview
main branch  ->  PROD env   ->  Convex prod deployment, wrapper-relay-prod, Vercel Production
```

## How each component picks dev vs prod

- **web (Vercel)**: Vercel's Git integration decides by the Production Branch
  setting. With Production Branch set to `main`, `main` deploys to Production and
  every other branch and PR deploys to Preview. No GitHub workflow is involved.
- **backend and relay (GitHub Actions)**: the deploy workflows select a GitHub
  Environment from the branch, so secrets and variables resolve per environment.

| Workflow             | Trigger                                                | Deploys                                                |
| -------------------- | ------------------------------------------------------ | ------------------------------------------------------ |
| `deploy-backend.yml` | push to `dev` or `main` touching `packages/backend/**` | Convex (`convex deploy`)                               |
| `deploy-relay.yml`   | push to `dev` or `main` touching `apps/relay/**`       | Fly app (`flyctl deploy`)                              |
| `ci.yml`             | every PR and push                                      | lint, types, tests, web build, relay smoke (no deploy) |

## Secrets, in short

- **Convex** (per deployment): `ENVIRONMENT`, `SITE_URL`, `BETTER_AUTH_SECRET`,
  `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `AUTUMN_SECRET_KEY`.
- **Fly relay** (per app): `CONVEX_URL`.
- **Vercel web** (per scope): `NEXT_PUBLIC_CONVEX_URL`,
  `NEXT_PUBLIC_CONVEX_SITE_URL`.
- **GitHub Environments** (`dev`, `production`): `CONVEX_DEPLOY_KEY`,
  `FLY_API_TOKEN`, and the `FLY_APP_NAME` variable.

Generate a `BETTER_AUTH_SECRET` with `openssl rand -base64 32` and set a
different value per environment.

## Local development

Run the pieces in separate terminals:

```bash
# backend (Convex dev deployment + live codegen)
cd packages/backend && bunx convex dev

# relay (point it at your Convex dev URL)
cd apps/relay && CONVEX_URL="https://<your-dev>.convex.cloud" bun run dev

# web (optional, for the auth and onboarding UI)
cd apps/web && bun run dev

# cli
cd apps/cli && bun run index.ts auth login && bun run index.ts shell-host
```

`packages/backend/.env.local` holds your local Convex URL and
`AUTUMN_SECRET_KEY`. Point the CLI at local by copying `apps/cli/.env.example`
to `apps/cli/.env`.

## Deploy flow

Push to `dev` to deploy the dev backend and relay and a Vercel Preview. Merge to
`main` to deploy everything to prod. See `ENVIRONMENTS.md` for the one-time setup
checklist (Vercel import, Convex deploy keys, Fly apps, GitHub Environments,
OAuth apps, and Autumn config).
