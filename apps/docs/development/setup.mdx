## Prerequisites

- Bun 1.3.5 or newer
- macOS or Linux
- A Convex development deployment

From the repository root:

```bash
bun install
```

## Start the services

Run each command in a separate terminal.

Backend:

```bash
cd packages/backend && bunx convex dev
```

Relay (point at your Convex `.cloud` URL):

```bash
cd apps/relay
CONVEX_URL="https://<your-dev>.convex.cloud" bun run dev
```

Web:

```bash
cd apps/web && bun run dev
```

CLI host:

```bash
NODE_ENV=development \
  WRAPPER_CONVEX_URL="https://<your-dev>.convex.cloud" \
  WRAPPER_RELAY_URL="ws://localhost:8080" \
  WRAPPER_AUTH_ORIGIN="http://localhost:3000" \
  bun run --cwd apps/cli dev:host
```

Or equivalently:

```bash
NODE_ENV=development bun run apps/cli/index.ts shell-host
```

Released CLI binaries use production endpoints when `NODE_ENV` is unset.
Development must set explicit Convex, relay, and auth URLs.

The complete environment and deployment matrix lives in
[`ENVIRONMENTS.md`](https://github.com/heycupola/wrapper/blob/main/ENVIRONMENTS.md).

## Local quality checks

```bash
bun run lint
bun run format:check
bun run check-types
bunx turbo run test
bun run --cwd packages/backend test:integration
```

Docs:

```bash
bun run --cwd apps/docs build
bun run --cwd apps/docs dev
```

## Relay smoke check

```bash
RELAY_URL="https://relay.example.com" bun run --cwd apps/relay smoke
```

This checks relay health and rejects an unauthenticated WebSocket request.

## Manual end-to-end check

1. `NODE_ENV=development wrapper auth login` (or the source CLI equivalent)
2. Start a host and share with `Ctrl+\` then `s`
3. Attach from another terminal with `--relay --id <sessionId>`
4. Detach with `Ctrl+\` then `d`
5. Unshare with `Ctrl+\` then `u`
6. Watch the title for `relay` then optionally `p2p`
7. Repeat with `WRAPPER_P2P=0` and confirm it stays on `relay`

NAT-restricted networks and CI sandboxes often cannot form WebRTC. Relay-only
success is still a valid result.
